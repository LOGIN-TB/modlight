# Podlight 0.7.2

## Fixed

- **A machine whose card does not work is named as such.** On some RunPod machines the container cannot reach the card at all: "CUDA unknown error", before the model is even loaded. This was seen twice on RTX PRO 6000 Workstation hosts, while the same model started fine on a B200. Podlight used to report this as a failed model. It now says that the machine is at fault, and offers "Start on a New Card…" (or choose another card type under Edit).
- **The error shown is the engine's own.** vLLM runs its engine in a separate process. When that process fails, the last lines in the log are the API server's "See root cause above", and that is what Podlight showed. It now shows the engine's error line instead, on the Mac and on servers.
- **Show Engine Log.** After a failed start, the model page offers "Show Engine Log…" with the engine's last 250 lines, to read or copy.
- **Failed starts no longer keep their disk forever.** A failed start whose pod keeps its disk now counts towards the deletion period like a stopped one. Before, it was billed until you acted.

## Deutsch

- **Ein Rechner, dessen Karte nicht funktioniert, wird als solcher benannt**: Auf manchen RunPod-Rechnern erreicht der Container die Karte gar nicht („CUDA unknown error“), noch bevor das Modell geladen wird. Gesehen zweimal auf RTX PRO 6000 Workstation; dasselbe Modell startete auf einer B200 problemlos. Podlight meldet jetzt, dass der Rechner schuld ist, und bietet „Auf neuer Karte starten …“ an.
- **Angezeigt wird die eigentliche Fehlerzeile der Engine** statt vLLMs „See root cause above“, auf dem Mac und auf Servern.
- **„Engine-Log anzeigen …“** öffnet nach einem Fehlstart die letzten 250 Zeilen zum Lesen oder Kopieren.
- **Fehlgeschlagene Starts behalten ihre Festplatte nicht mehr unbegrenzt**: Sie zählen jetzt wie gestoppte Pods zur Löschfrist.
