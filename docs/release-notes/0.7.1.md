# Podlight 0.7.1

## Fixed

- **"Can't load image processor".** Some quantised uploads of image-and-text models (for example Qwen3.5 MoE in NVFP4) leave out the image processor that vLLM needs, so the engine stopped right after the download. The pod now checks this before vLLM starts and, for such a model, serves its text part (`--language-model-only`). That is all a coding agent uses. Models that do have their image processor keep reading images.
- **Kept pods vanished before their deletion date.** When a stopped pod with "Keep model on disk" was started (by you or by an agent's request) and the card on its machine at RunPod was taken, Podlight deleted the pod with its disk at once and built a new one, which downloaded the model again. RunPod reports a taken card often, sometimes just seconds after a stop. Podlight now tries again for about a minute. If the card stays taken, the pod and its disk are kept, and the model page offers "Start on a New Card…" for when you want a new pod. A stopped pod without any recorded date (from an older state) no longer counts as unused since forever: its deletion clock starts when it is first seen.
- **Kept pods get this version's start script.** A pod stopped with "Keep model on disk" used to resume with the start script and watchdog of the version that created it, so fixes like the one above did not reach it. Before a resume Podlight now puts in the current ones. RunPod keeps the pod stopped while doing so. Works on the Mac and on servers.

## Deutsch

- **„Can't load image processor“**: Manche quantisierten Kopien von Bild-und-Text-Modellen (etwa Qwen3.5-MoE in NVFP4) lassen die Bildverarbeitung weg, die vLLM braucht. Die Engine brach dann direkt nach dem Download ab. Jetzt prüft der Pod das vor dem Start und lässt ein solches Modell nur mit Text laufen (`--language-model-only`). Mehr nutzt ein Coding-Agent ohnehin nicht. Modelle mit Bildverarbeitung lesen weiterhin Bilder.
- **Pods mit Festplatte verschwanden vor ihrer Löschfrist**: Wurde ein gestoppter Pod mit „Modell zwischenspeichern“ gestartet, von dir oder durch die Anfrage eines Agenten, und war die Karte auf seinem Rechner bei RunPod belegt, löschte Podlight den Pod samt Festplatte sofort und legte einen neuen an, der das Modell neu lud. Jetzt versucht Podlight es etwa eine Minute lang erneut. Bleibt die Karte belegt, bleiben Pod und Festplatte erhalten, und die Modellseite bietet „Auf neuer Karte starten …“ an.
- **Gestoppte Pods bekommen das aktuelle Startskript**: Ein mit „Modell zwischenspeichern“ gestoppter Pod lief beim Fortsetzen mit Startskript und Watchdog der Version, die ihn angelegt hat. Korrekturen wie die obige erreichten ihn deshalb nicht. Jetzt setzt Podlight vor dem Fortsetzen die aktuellen ein, auf dem Mac und auf Servern.
