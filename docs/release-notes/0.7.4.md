# Podlight 0.7.4

## Fixed

- **A busy machine no longer costs you the downloaded model.** A pod with a kept disk resumes on the machine it lives on. When that machine has given its card away (common on Community Cloud right after an idle stop), Podlight used to try for a minute and then offer only "Start on a New Card…", which deleted the old pod and its disk at once, so the model was downloaded again. Now:
  - Podlight keeps trying to resume the pod every 30 seconds, in the background, until the end you chose when starting it (half an hour for a start a request woke). The model shows "Waiting for a card" with a "Stop Waiting" button, instead of an error.
  - "Start on a New Card…" keeps the old pod and its disk until the new pod answers and passes the start test. Only then is the old one deleted. If the new one fails, hangs or is stopped before it answers, it is deleted instead and the old pod is the model's pod again.
- **A hung engine is stopped.** If a loading pod shows no progress for 10 minutes (no download onto its disks, no new log line, no graphics memory taken, no CPU use), Podlight stops it with "The engine made no progress while loading" and offers "Start on a New Card…". Before, a llama.cpp pod that hung at "initializing" kept billing until the end of the run. The pod's watchdog now reports the size of the engine log for this.
- "Resuming takes about a minute" now shows only when a pod really resumes, not for a new pod of a model with a kept disk.
- All of this works on the Mac and on servers. Help: updated in "Costs and safety", new entry in Troubleshooting.

## Deutsch

- **Eine belegte Maschine kostet nicht mehr das geladene Modell.** Ein Pod mit behaltener Festplatte wird auf seiner Maschine fortgesetzt. Hatte diese ihre Karte weitergegeben (in der Community Cloud nach einem Leerlauf-Stopp häufig), versuchte Podlight es eine Minute lang und bot dann nur „Auf neuer Karte starten …“ an. Das löschte den alten Pod samt Festplatte sofort, und das Modell wurde neu geladen. Jetzt:
  - Podlight versucht im Hintergrund alle 30 Sekunden, den Pod fortzusetzen, bis zu dem Ende, das du beim Start gewählt hast (eine halbe Stunde bei einem Start durch eine Anfrage). Das Modell zeigt „Wartet auf eine Karte“ mit dem Knopf „Warten beenden“ statt einer Fehlermeldung.
  - „Auf neuer Karte starten …“ behält den alten Pod und seine Festplatte, bis der neue antwortet und den Starttest besteht. Erst dann wird der alte gelöscht. Scheitert oder hängt der neue oder stoppst du ihn vorher, wird stattdessen er gelöscht, und der alte ist wieder der Pod des Modells.
- **Eine hängende Engine wird gestoppt.** Zeigt ein ladender Pod zehn Minuten lang keinen Fortschritt (kein Download, keine neue Log-Zeile, kein Grafikspeicher, keine CPU-Last), stoppt Podlight ihn mit „Die Engine kam beim Laden nicht voran“ und bietet „Auf neuer Karte starten …“ an. Bisher kostete ein llama.cpp-Pod, der bei „initializing“ hing, bis zum Ende des Laufs weiter.
- „Fortsetzen dauert etwa eine Minute“ erscheint nur noch, wenn wirklich fortgesetzt wird.
- Auf dem Mac und auf Servern. Hilfe: „Kosten und Sicherheit“ ergänzt, neuer Eintrag unter „Wenn etwas nicht klappt“.
