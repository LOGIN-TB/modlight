# Podlight 0.10.0

## New

- **More of what a running model does, in tiles.** Under "Usage" the engine's figures are now tiles instead of a list:
  - **Writing** and **Reading:** tokens per second while the model answers and while it reads the prompt, over the latest requests. Between requests the last value stays; before, the list showed "0 tokens/s" as soon as no request ran.
  - **Prompt cache:** the share of prompt tokens taken from the engine's cache instead of being read again. Agents such as Claude Code send the whole conversation with every request; a high share makes answers quick.
  - **Since the start:** tokens read and written. Also **Requests**, with vLLM the **Context cache**, and the **Card** with temperature and power.
  - The pod's watchdog reads these from llama.cpp and vLLM. They appear for pods started or resumed with this version.
- **The usage rings fill the width.** They spread across the whole row and wrap when the window is narrow or the pod has several cards. Memory and disks turn orange from 85 % and red from 95 %.

## Changed

- **Next steps count a server.** If RunPod, a model and an agent are set up on a paired server, the overview no longer asks you to add or start a model on this Mac. The list shows only open steps, with how many are done. It disappears once every required step is done; the optional Hugging Face token alone no longer keeps it up.
- **"Now" names the card** of each running model, such as "L40S" or "2 × RTX A6000".
- **Spending rows** read like every other row: the name on the left, the amount on the right, the bar beneath.

## Deutsch

- **Mehr davon, was ein laufendes Modell tut, in Kacheln.** Unter „Auslastung“ stehen die Werte der Engine jetzt als Kacheln statt als Liste:
  - **Schreiben** und **Lesen:** Token pro Sekunde beim Antworten und beim Einlesen des Prompts, gemessen an den letzten Anfragen. Zwischen Anfragen bleibt der letzte Wert stehen. Bisher zeigte die Liste „0 Token/s“, sobald keine Anfrage lief.
  - **Prompt-Cache:** welcher Anteil der Prompt-Tokens aus dem Cache der Engine kam, statt neu gelesen zu werden. Agenten wie Claude Code schicken bei jeder Anfrage den ganzen bisherigen Verlauf; ein hoher Wert macht die Antworten schnell.
  - **Seit dem Start:** gelesene und geschriebene Tokens. Dazu **Anfragen**, bei vLLM der **Kontext-Cache** und die **Karte** mit Temperatur und Leistung.
  - Der Watchdog im Pod liest diese Werte aus llama.cpp und vLLM. Sie erscheinen bei Pods, die mit dieser Version starten oder fortgesetzt werden.
- **Die Ringe der Auslastung nutzen die ganze Breite.** Sie verteilen sich über die Zeile und brechen um, wenn das Fenster schmal ist oder der Pod mehrere Karten hat. Arbeitsspeicher und Festplatten werden ab 85 % orange und ab 95 % rot.
- **„Nächste Schritte“ zählen einen Server mit.** Sind RunPod, ein Modell und ein Agent auf einem gekoppelten Server eingerichtet, fordert die Übersicht nicht mehr auf, auf diesem Mac ein Modell anzulegen oder zu starten. Die Liste zeigt nur noch offene Schritte und wie viele erledigt sind. Sie verschwindet, sobald alle Pflichtschritte erledigt sind; der optionale Hugging-Face-Token allein hält sie nicht mehr offen.
- **„Jetzt“ nennt die Karte** jedes laufenden Modells, etwa „L40S“ oder „2 × RTX A6000“.
- **Die Ausgaben-Zeilen** sehen aus wie alle anderen Zeilen: Name links, Betrag rechts, Balken darunter.
